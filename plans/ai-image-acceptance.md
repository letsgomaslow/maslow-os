# Preinstalled AI image: implementation and acceptance

## Product boundary

Maslow retains its approved branding and Omarchy-compatible system/update contracts. The supported candidate is x86_64; Apple Silicon is the development host, not a new ARM release requirement. Power users receive the core AI tools already installed. Onboarding selects and configures tools, and leaves unselected tools installed without starting unnecessary services. No new installer framework or cosmetic redesign is required.

The initial core is Bitwarden, Codex, Claude Code, and Hermes CLI with its built-in memory. Additional external memory, vector database, and graph integrations remain optional; their presence in a future roadmap is not evidence they are packaged or supported. Do not bundle duplicate Hermes Desktop ownership or large models by accident.

## Implementation sequence

1. Establish one package/installation owner for each core tool and include it in the existing canonical package list and ISO offline mirror. Prevent first-run wrappers from shadowing packaged executables.
2. Make onboarding configuration-first, with explicit missing-software errors, resumable selection, separate sign-in confirmation, and no automatic high-permission consent. Deselecting never uninstalls a tool.
3. Reduce demonstrated repeated readiness work and improve performance diagnostics without removing branding, accessibility, or trust checks.
4. Build and test the coordinated runtime, package, and installer candidate. Preserve existing VM disks and configure automated access in a disposable acceptance environment before relying on it.

## Current constraints

The frozen candidate proves the bounded preinstalled core gate, not release readiness. Do not retry destructive installer recovery or request manual VM typing. Existing accepted installations and finalized assets must remain intact.

Remaining gates are a usable rendered Bitwarden desktop, actual provider sign-in and secret-handling checks, missing-tool behavior in the installed flow, restoration or reproduction of auditable upstream idle evidence, matched active-window responsiveness and native-hardware verification, and visual approval of the complete boot, login, desktop, onboarding, and terminal branding journey. The bounded matched idle comparison was historically observed, but missing upstream raw artifacts prevent final acceptance; it does not close these other gates. Update/reboot preservation also remains unverified.

Source review confirms an additional release risk: the inherited upstream package channels can replace the Maslow runtime and its branded surfaces. That mutation has not been tested against this candidate, so channel/update behavior must be constrained and verified before public release.

Exact revisions and dirty-patch provenance for every runtime, package, and ISO input are not yet complete, and public distribution licensing and redistribution rights have not been cleared. Do not describe this artifact as a clean-source, fully tested, licensed, or release-ready build.
