## Behavior and implementation

The user requested that the orb match whichever desktop theme is active. [Panel.qml](../../voice/ui/Panel.qml) now imports the existing `qs.Commons.Color` singleton and passes its live accent/background into the orb. The same singleton receives the supported shell theme-switch payload, so bindings update without changing Voice preferences or restarting its conversation. Voice details, status, badge, selections and controls use popup and foundational theme roles. Text, alerts, button labels and selections choose or adjust contrast for light and dark palettes. Existing popup border overrides are honored. Surfaces are opaque to keep text contrast predictable over arbitrary desktop content.

[VoiceOrb.qml](../../voice/ui/VoiceOrb.qml) derives its light/base/shade gradient from the supplied accent. [The GPU shader](../../voice/ui/VoiceOrb.frag) takes the same three colors as uniforms. Software Canvas listens for palette changes even while paused or reduced motion is enabled; it does not depend on an animation tick to repaint. Face, microphone indicator and focus ring select contrasting ink. The fluid geometry, allocations, interaction and audio signals are unchanged. The user's saved Reduce voice motion selection is preserved.

One subagent handled Panel/control theme integration and contrast regression checks; the coordinator implemented both orb renderers, reviewed integration and ran native/package checks. No installed core, user theme, credential or conversation policy was edited.
