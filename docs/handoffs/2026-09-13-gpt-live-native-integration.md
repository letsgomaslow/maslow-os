## Implemented behavior

GPT-Live is integrated into the native Voice provider path as `gpt-live-1` full-duplex audio. It keeps continuous input/output audio and transcript fragments, emits client delegation notices, and leaves interpretation and authorization to the host. The host creates a bounded transcript-backed brief at delegation time and submits it to a separate native Hermes executor. The conversation provider does not execute tools or become the task executor.

The native task path uses Hermes's `openai-api` provider and its separate model/profile configuration. Conversation credentials, Hermes configuration, Codex configuration, and Claude credentials remain separate. Exact cancel/redirect phrase handling is bounded to the sole active task; this integration does not claim a general natural-command guarantee.

The UI exposes GPT-Live as a selectable mode with the voice selector and OpenAI conversation credential field. LiveKit setup now presents Project URL, API key, and API secret together with **Save LiveKit setup**; blank credential fields retain existing keyring values. These UI claims are based on the current source and fast rendering evidence below.

## Controller recovery correction

A service restart exposed another product defect: watch input used a blocking stdin read in a worker thread. Cancelling its asyncio task did not unblock that thread, so the watch process could remain alive after server EOF and prevent the native panel from reconnecting. `564f3b26` uses an event-loop stdin pipe, propagates bounded request errors, and retries the QML connection after an unexpected exit. Two real subprocess regressions verify server EOF with stdin still open and rejection of oversized input without forwarding it. One initial test race was fixed by waiting for the server handshake; production checks were not weakened. The final SDK suite passes.
