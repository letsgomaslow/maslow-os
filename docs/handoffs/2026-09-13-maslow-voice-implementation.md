## Delivered behavior

- One Maslow orb: grey and bottom right when disabled/idle, bottom center in conversation, bottom left for work/results/attention, including after Voice is switched off. Placement holds during interaction; fixed position, display preference and reduced motion are available.
- Talk, Type, Tasks and Settings inside the existing Quickshell process. Voice off releases audio and invalidates pending conversation turns without cancelling independent tasks. Lock ends the live conversation. Status and Voice off remain responsive during long provider, download or readiness requests.
- Strict OpenAI Realtime, LiveKit Expressive, Ollama/LM Studio server, and fully offline modes. Credentials use the desktop keyring; there is no automatic provider fallback. Local speech assets are pinned and verified. Language models are selected from the user's existing manager/store rather than downloaded by Voice.
- Conversation can answer or submit a summarized work brief. A separate local Hermes Runs service receives the immutable turn/project/mode and can route coding through structured Codex App Server and Claude Agent SDK adapters. A2A is deferred. Child approvals, steering, cancellation, continuation and durable task reconciliation are implemented.
- Offline work uses a private copied project, dedicated disconnected Ollama/Hermes/coder processes, and a separate trusted Weston window. Original files, host home, credentials, runtime/IPC and network access are excluded from the executor. Export requires stopped execution, an explicit desktop action, a matching review digest and unchanged source fingerprints. The current UI shows paths/actions and exports the displayed list; content diffs and per-file selection are not implemented.

## Failures found and corrected

- Plain `qsb` omitted GLSL variants and the real OpenGL pipeline failed. The recipe now compiles explicit GLSL variants and the running shader passed.
- Archive inspection found uv's unused writable build lock. The package now excludes it; the final complete archive metadata and source-byte comparisons passed.
- Installed Qt ComboBox defaults produced white text on a white background. Voice now supplies explicit dark control/popup/delegate styling.
- Long IPC requests blocked status and Voice off. Request serialization now preserves ordinary FIFO ordering while immediate safety controls bypass it; cancellation invalidates older queued voice work. Audio/provider cleanup remains bounded and attempts provider shutdown even if transport shutdown fails.
- Offline model discovery incorrectly depended on an active runtime/selected model, and readiness retained temporary workspaces. Discovery now reads the existing Ollama store; readiness cleans its test runtime, and stopped snapshots remain reviewable after restart.
- The nested Weston startup budget was too short for observed software-rendered startup. It is bounded at 30 seconds and still fails closed when no private compositor appears.
- Hermes requires the top-level enabled-plugin list. The shared host/offline profile generator now supplies it, verified against the pinned loader.
- A separate actual-Hermes diagnostic reached the authenticated Runs capabilities endpoint and shut down cleanly within 94.45 seconds in the 1.5 GB TCG guest. The original 30-second online startup allowance was insufficient for this cold start. Online and offline startup now use a monotonic 120-second deadline, retain capability validation and cancellation, and give the enclosing offline RPC 135 seconds for startup plus cleanup. Evidence: `voice-installed/hermes-startup-diagnostic-result.json`.
- An accepted native Runs task then triggered unrelated lazy dependency checks, followed by Hermes's loop watchdog exiting with code 75. Dedicated profiles now set the pinned `security.allow_lazy_installs: false` opt-out and `HERMES_DISABLE_LAZY_INSTALLS=1`; the previously used `HERMES_NO_AUTO_INSTALL` was not a supported control. The actual pinned helper verified the opt-out. Tirith and other upstream security checks remain enabled. The next native run reached completed/READY; this is a local model-protocol fixture, not paid inference.
- Confirmed local coordinator exit previously left a task reconnecting indefinitely. The daemon now marks it interrupted, retains its run identity, cancels dependent children and offers explicit Continue. This includes an offline worker exit and an owned Hermes child exit while that worker remains alive; the latter uses one exact allowlisted error object and cleans its owned session group. Known-dead process caches are discarded for the next attempt; a transient HTTP failure alone never triggers resubmission. A continuation arriving during event-stream cleanup is retained until the prior monitor finishes.
- The final fixture's unconditional plugin rescan ran while the desktop was locked. Investigation found the rescan at 17:15:34, followed by journaled stranded-lock recovery at 17:15:40 and `Tried to show lockscreen surfaces without active lock` at 17:16:00. Crash dumping/reporting consumed memory and the following Hermes cold start timed out before any model request. Three Quickshell process rows included crash handling; they do not prove three live desktop shells. Supported shell recovery restored the lock screen, QMP input authenticated the fixture account, and the settled Hermes rerun passed without changing its deadline. Voice install/open helpers now defer on locked, pending or unknown lock state; a private runtime marker preserves upgrades until an explicit safe open. Disabled plugins stay disabled and marker writes/openers share one lock. The generic shell rescan implementation is unchanged: these are preflight guards, not a new atomic global reload/lock protocol. Preserve this broader platform race as a release acceptance concern. Evidence: `voice-installed/guest-resource-after-hermes-timeout.log`, `guest-shell-process-diagnostic.log`, `shell-recovery-final.log`, `voice-locked-open-final.log`, and `locked-rescan-journal.log`.
- The first 1 GB TCG guest swapped heavily. Hermes did not bind before its 30-second readiness limit; isolated model inference exceeded its 150-second probe limit. These were failures, not passes. A 1.5 GB guest and bounded 64 MB TCG translation cache resolved the isolated inference failure without weakening its production check. Existing unrelated Docker environments were preserved.
- The guest's stale mirror referenced an unavailable Ollama package. The fixture installed the current signed Arch archive through a local transaction. No standalone package-database refresh, runtime-hold bypass, or product mirror change was used to disguise a fresh-install result.

## Remaining acceptance

Live OpenAI and LiveKit Expressive audio require real provider credentials and a live session. Physical microphone/speaker echo, interruption and latency, actual local model conversations and coding quality, sustained offline application interaction, the complete speech-to-task-to-reviewed-export journey, multi-monitor placement, pointer behavior outside the input mask and Lenovo acceptance remain separate gates. CPU-only offline support should not be presented as GPU-accelerated support. A visible orb, successful package install or mocked model response does not close these gates.

Before promotion, integrate the three coordinated source branches through review, build exact packages from clean recorded commits, and test the selected real provider/model plus installed update/recovery. Publication, signing, channel changes, ISO redistribution and hardware changes require their own existing release process. No release promotion follows from this handoff.

Next executable acceptance step: on the intended x86 device, enter the selected provider's credentials through Voice Settings and exercise a conversation, interruption, Voice off with a continuing task, an explicit approval and a completed result. Then repeat with the chosen downloaded local model and a stopped, reviewed offline export. Include locked installation/upgrade and a lock occurring during refresh when reviewing the underlying platform reload race.
