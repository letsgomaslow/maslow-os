# Maslow plugin curation

Maslow OS should curate upstream Omarchy plugins rather than fork eleven new products. Keep every upstream plugin ID, author, license, and update relationship intact. Maslow may supply a user-facing label or approved logo in its own onboarding and menu surfaces, but it must not rename the plugin internally or remove author credit.

The marketplace is a discovery source, not a security guarantee. Its installer currently clones a repository's mutable branch, so release work must review and pin the exact commit recorded below before any plugin is shipped. No plugin belongs in the installer until it passes source review, Omarchy compatibility checks, native x86 acceptance, theme switching, removal, and an idle-resource measurement. The states below are proposals pending those reviews, not claims that any plugin is installed. Review gates defer an item; they do not remove it permanently from the planned eleven-plugin curated bundle.

This pass inspected the current code of Dock, App Launcher, Lock Screen Explorer, and Omaland at their listed commits. The other seven entries are based on their pinned manifests and documented behavior and still require a full source audit before release.

## Recommended first pilot

Pilot only Dock and App Launcher. Present them as optional Maslow workspace choices, not replacements for Omarchy's package manager or plugin system.

- **Dock:** keep ID `omadock` and credit thepathless. Maslow's product UI may label it **Maslow Dock** and provide the approved Maslow launcher mark through a small downstream configuration or upstreamable asset hook. Do not edit the plugin name, repository identity, license, or Omarchy command targets. Start with theme colors, reduced motion, notification sound off, folder stacks off, and no extra Hyprland keybindings. The manifest keeps the overlay loaded, and its visible intelligent-autohide path can run `hyprctl -j clients` every 350 ms, so the README's zero-CPU claim is not release evidence; measure it on target hardware. Its stated minimum is Omarchy 4.0.1+, while the current Maslow base is a 4.0 alpha fork, so compatibility is not yet proven.
- **App Launcher:** keep ID `tyrsolution.app-launcher` and credit Tyrsolution. Maslow's product UI may label it **Apps** and use an approved Maslow icon. Enable the overlay only, omit the optional bar widget, and use the reviewed `Super+A` binding without replacing `Super+Space`, `Super+Alt+Space`, or `Super+Shift+A`. It follows `qs.Commons` theme tokens and has no continuous service, but its optional wizards write desktop entries and a custom-agent file, and its remove action can uninstall packages in a visible privileged terminal. Those actions must remain explicit user choices. It targets Omarchy 4.x and Quickshell 0.3+, but still needs validation against the exact Maslow shell commit.

Do not merge the two codebases. Maslow should own only the curated menu placement, approved display labels, initial settings, and acceptance tests. Upstream remains the code and update owner.

## Release gates

1. Re-review each pinned commit and record any upstream drift; never silently substitute mutable `HEAD`.
2. Validate manifests and QML against the exact Maslow shell/Quickshell build, including plugin add, enable, disable, update, and remove.
3. Switch through every shipped Maslow theme and at least one upstream Omarchy theme. Check contrast, focus, reduced motion, spacing, icons, and that display labels do not replace upstream credit.
4. Compare idle CPU and memory before and after each enabled plugin on native x86 hardware. Polling or always-loaded plugins must have measured budgets, not README claims.
5. Confirm every config write is scoped, reversible, and backed up. Removal must not leave broken menu rows, services, mounts, keybindings, or disabled first-party plugins.
6. For lock/boot changes, require a disposable VM recovery test with the stock Maslow lock and boot path still available. No lock plugin is part of the first pilot.
7. For provider-connected plugins, show the network/auth boundary before enabling. Maslow must not store provider credentials or imply that account connection is complete without provider evidence.

## Next step

Build a disposable native-x86 acceptance package containing only the reviewed Dock and App Launcher commits. Apply only the approved Maslow dock glyph and tooltip patch while keeping the original IDs, origins, licenses, and credits intact. Test the reviewed `Super+A` binding with no optional bar widget, account connection, or lock-screen change. If that pilot passes compatibility, visual, removal, and performance gates, evaluate Hardware Tooltip next; keep the remaining plugins inactive or behind the review gates above.
